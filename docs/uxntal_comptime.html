Experimenting with compile-time blocks in Uxntal.

In my Uxntal programs I make heavy use of compile-time (or assembly-time, if you will) features to avoid computing various constants at runtime. This is typically done via labels and the “cursor” (sometimes also called “head”) — an internal register of the assembler that points at the position of the next byte that will be written to the ROM. The cursor increments automatically on each byte written, but it can also be set to a particular value with the absolute padding rune (“|”) or incremented by a particular amount with the relative padding rune (“$”). The “constants” are in reality labels that got defined when the cursor had a specific value. Bonus: as a side-effect of the zero-page check, constants with values greater than 255 have an out-of-the-box compile-time assert that makes sure they're not used in byte contexts (“.” and “-”) which would result in potentially unwanted truncating. Pretty neat.

This approach is often used for defining enumerations, bitmasks, and structures. The device labels in pretty much all Uxntal programs are typically a kind of enumeration.

Further reading: “Uxntal Labels”

Unfortunately, addition, subtraction of a known constant, and multiplication by a known constant can only get you so far. If you want your value to be a result of a division, modulo, or maybe even a bitwise operation, you're out of luck and have to rely on other options.

One of such options is to compute these values in a metaprogram (i.e. program that generates code), which complicates the build process if the values are tweaked often. This is what I did for Bad Apple!!, see: constants.tal

Another option is to compute these values at the very start of the program. If a value is used once, write it there and you're done. However, if a value is used multiple times in the program, you would either have to keep track of all these places separately and write the value to each one, or keep the value in a separate location and load it at runtime. Neither of these options sounds appealing to me.

Drifblim

As of 2026, Drifblim is the standard Uxntal assembler, written in Uxntal itself. It is running on the same architecture it targets. If an assembler running on Uxn is assembling Uxntal anyway, couldn't it execute some of the code it's assembling?

The compile-time blocks in my proof-of-concept implementation come in two flavors: “~{ … }” and “|{ … }”.

Each compile-time block can be thought of as a separate mini-program executed by the assembler. I also call these “escape blocks” because you “escape” the assembler to execute a piece of arbitrary code.

Try them yourself:

drifblim-escapes.patch

Encountering a compile-time block puts the assembler into a special mode (similar to one when defining a macro) in which words are assembled into a separate region in memory, up until a terminating “}”. Then, the assembler quite literally jumps to that region as it it was a procedure in Drifblim's internals. Once it reaches the end of the block, it returns back to regular assembling, but before that, it does one of two things:

  • If we have just exited the “|{ … }” block, the cursor is set (as if it was set by a regular “|” rune) to the short on the top of the working stack.
  • If we have just exited the “~{ … }” block, all bytes that have been pushed onto the working stack inside the block are baked into the final ROM (which limits their size to the size of the working stack).

Code in such blocks can define new macros and labels, but these will not be available beyond that particular block. External macros (ones defined outside of the blocks) can be expanded due to how macros work internally in Drifblim. External labels can be referenced (unless relative) but any external code cannot be jumped to and executed (it is in a different address space, after all).

I have a feeling there's something fundamentally raw going on about the escaping, some kind of primal computing concept akin to Forth's compile mode, a strange loop closing. But maybe I'm just tooting my own horn. I'll leave that for someone else to think about.
